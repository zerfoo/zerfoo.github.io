# Zerfoo: native intelligence

POV: a compact, legible engineering brand with one luminous copper horizon. The product is presented as inference inside a Go application. The hero adapts the supplied Xero reference to Zerfoo rather than reproducing another product's identity or unsupported customer logos.

User-authorized choice: complete rebrand. Existing Hugo architecture and documentation routes are retained. The user supplied a detailed dark visual reference and delegated branding choices; this is treated as sufficient direction to implement a concrete design without an extra direction-selection gate.

## Three checkable laws

1. One drama surface: the warm arc and model → runtime → app pipeline in the hero. Other sections remain neutral and static.
2. Every performance number names its model and exposes source conditions; model registration is never presented as verification.
3. Every section leads to working code, published evidence, a documentation route, or the builder. No fabricated customer logos, adoption counts, or launch badges.

## Identity

A geometric Z cut from a copper tile. The top and bottom offsets evoke a passage through the runtime. Warm neutral backgrounds, warm white primary text, copper accent. Inter is self-hosted. Logo is vector and scales down to the favicon. No trademark-registration claim.

Token layer: static/css/site.css. Named spacing scale 4, 8, 12, 16, 24, 32, 48, 64, 96, 128. Radii 8, 16, 24, pill. Type roles: display, section, card, body, small, mono label. Documentation extends its existing Sass variables with warm light/dark pairs.

## Deliberate deviations from skill defaults

- Single dark marketing art direction follows the supplied reference; system light preference does not invert the landing illustration. Docs remain system-adaptive and are captured in both schemes.
- Inter and a CSS/SVG pipeline follow the explicit design reference. An extra set of three candidate screens would add an unrequested approval gate after the user delegated the decision.
- Keep Hugo instead of adding a React build solely for a hero animation. The reference's visual and interaction intent is implemented with plain CSS and a small local script.
- SVG represents interface geometry and brand assets; no generated raster assets are required.

## Motion

Four phases: 800 ms model-to-runtime beam, 800 ms runtime pulse, 800 ms runtime-to-app beam, 1000 ms idle. Beam positions derive from actual node bounds and resize. Stop on hidden tab or offscreen pipeline. Reduced-motion disables beam/pulse and keeps the complete static path readable. Hover transitions stay within 200 ms; mobile navigation 350 ms with keyboard trapping, Escape, and scroll restoration.
